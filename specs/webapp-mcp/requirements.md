# webapp-mcp（Web アプリ連携 MCP サーバ）要件定義

## 概要

利用者（1 人）が、Claude（Web・Desktop・モバイルアプリ）、Claude Code、Microsoft 365 Copilot などの AI から、Web アプリ（`claude_webapp`）の 4 機能（スケジュール、グッズ管理、ノウハウ管理、経費管理）のデータを参照・登録・更新・削除できるようにする MCP サーバである。

MCP サーバはインターネット上に常駐し、接続先の Web アプリ（サイト）ごとに保持した API キーで Web アプリの API を呼ぶ。対象とする操作は、各機能の主要なものに絞る。

## 用語

| 用語 | 説明 |
|------|------|
| MCP クライアント | MCP サーバに接続して、ツールを呼び出す AI のアプリ（Claude、Claude Code、Microsoft 365 Copilot など）。 |
| ツール | MCP サーバが MCP クライアントに提供する、1 つの操作の単位。 |
| サイト | 接続先の Web アプリ。識別子、表示名、各機能の接続先、API キーを持つ。複数を登録でき、1 つを既定とする。 |
| 既定のサイト | サイトの指定を省略したときに使うサイト。 |
| API キー | Web アプリの API キー管理機能で発行した、他システム連携用の秘密の文字列。MCP サーバがサイトごとに保持する。 |
| サインイン | MCP クライアントを MCP サーバに初めて接続するときに、利用者がパスフレーズを入力して接続を許可すること。 |
| パスフレーズ | サインインに使う、利用者だけが知る秘密の文字列。 |
| 予定 | スケジュール機能の予定と TODO の総称。 |

## 要件一覧

### REQ-001: サインインによる接続の許可

MCP クライアントが MCP サーバに初めて接続するとき、MCP サーバはサインインの画面を示し、利用者がパスフレーズを入力して許可したときだけ、その MCP クライアントの接続を認めること。

**受け入れ条件**

- 正しいパスフレーズで許可すると、その MCP クライアントからツールを使えるようになる。
- 誤ったパスフレーズ、または拒否を選んだときは、接続を認めない。
- サインインの画面には、接続しようとしている MCP クライアントの名前と、許可後に戻る先が示される。
- サインインの画面はスマートフォンの幅でも操作できる。
- 誤ったパスフレーズが続けて一定回数入力されたときは、一定時間、正しいパスフレーズでもサインインできない。
- パスフレーズは平文のまま保持されない。
- あらかじめ許可した種類の MCP クライアント（Claude、Claude Code、Microsoft 365 Copilot）以外からの接続の申し込みは受け付けない。

### REQ-002: 接続の維持と取り消し

一度サインインした MCP クライアントについて、MCP サーバは再度のサインインなしで一定期間ツールを使えるようにし、運用者が求めたときはすべての接続を取り消せること。

**受け入れ条件**

- サインイン後は、接続を維持している間、ツールを呼ぶたびにサインインを求めない。
- Claude の Web・Desktop で接続した場合、同じ Claude アカウントのモバイルアプリからもサインインなしで使える。
- 接続を維持できる期間は設定で変えられる。期間を過ぎたら、再度のサインインが必要になる。
- 運用者がすべての接続を取り消すと、すべての MCP クライアントで再度のサインインが必要になる。
- サインインしていない、または取り消された MCP クライアントからは、ツールを使えない。

### REQ-003: サイトの登録と選択

システムは、接続先の Web アプリ（サイト）を複数登録でき、ツールを使うときに対象のサイトを選べること。

**受け入れ条件**

- サイトは設定で登録し、それぞれに Web アプリの API キーを 1 つ持たせる。
- ツールでサイトを指定しないときは、既定のサイトを使う。
- 存在しないサイトを指定したときは、失敗としてその旨を示す。
- 登録済みのサイトの識別子と表示名を一覧で確かめられる。一覧に接続先の URL や API キーは含まれない。
- API キーは、そのサイトの Web アプリにだけ送られる。
- API キーが欠けているサイトがあるときは、MCP サーバは起動しない。

### REQ-004: スケジュールの予定の参照

利用者が期間を指定して予定を求めたとき、システムはその期間の予定を示すこと。予定の分類（カテゴリ）の一覧も示せること。

**受け入れ条件**

- 開始日と終了日を指定して、その期間の予定と TODO を取得できる。
- カテゴリの一覧を取得できる（予定の登録・更新でカテゴリを指定するため）。
- 返す内容は、Web アプリのスケジュール機能が返すものと同じ意味である。

### REQ-005: スケジュールの予定の登録・更新・削除

利用者が求めたとき、システムは予定と TODO を登録・更新・削除し、TODO の実施済み／未実施を切り替えること。

**受け入れ条件**

- 予定または TODO を登録できる。
- 登録済みの予定または TODO の内容を更新できる。
- 予定または TODO を削除できる。削除は元に戻せない操作として MCP クライアントに示される。
- TODO の実施済み／未実施を切り替えられる。
- 入力の誤りなどで Web アプリが受け付けなかったときは、失敗としてその理由（Web アプリが示す範囲）を示す。

### REQ-006: グッズの参照

利用者が求めたとき、システムはグッズの一覧と、1 件のグッズの詳細を示すこと。グッズの分類に使う人物・アーティスト・媒体の一覧も示せること。

**受け入れ条件**

- グッズの一覧を取得できる。
- 1 件のグッズの詳細を取得できる。
- 人物・アーティスト・媒体の一覧を取得できる（グッズの登録・更新で指定するため）。

### REQ-007: グッズの登録・更新・削除

利用者が求めたとき、システムはグッズを登録・更新・削除すること。

**受け入れ条件**

- グッズを登録できる。
- 登録済みのグッズの内容を更新できる。
- グッズを削除できる。削除は元に戻せない操作として MCP クライアントに示される。
- 入力の誤りなどで Web アプリが受け付けなかったときは、失敗としてその理由（Web アプリが示す範囲）を示す。

### REQ-008: ノウハウの検索と参照

利用者がキーワードを指定してノウハウを求めたとき、システムは該当するノウハウを示し、1 件のノウハウの詳細を示すこと。分類（大項目・中項目）の一覧も示せること。

**受け入れ条件**

- 1 つ以上のキーワードでノウハウを検索できる。
- 1 件のノウハウの詳細（タイトル・キーワード・本文）を取得できる。
- 大項目の一覧と、大項目ごとの中項目の一覧を取得できる（ノウハウの登録・更新で所属先を指定するため）。

### REQ-009: ノウハウの登録・更新・削除

利用者が求めたとき、システムはノウハウを登録・更新・削除すること。

**受け入れ条件**

- ノウハウを登録できる。
- 登録済みのノウハウの内容を更新できる。
- ノウハウを削除できる。削除は元に戻せない操作として MCP クライアントに示される。
- 入力の誤りなどで Web アプリが受け付けなかったときは、失敗としてその理由（Web アプリが示す範囲）を示す。

### REQ-010: 経費の参照

利用者が求めたとき、システムは支出記録の一覧と、予算期間の一覧、予算対実績の集計を示すこと。支出方法の一覧と、予算期間ごとの予算項目の一覧も示せること。

**受け入れ条件**

- 支出記録の一覧を取得できる。
- 予算期間の一覧を取得できる。
- 予算期間を指定して、予算対実績の集計（利用日基準、支払発生月基準）を取得できる。
- 支出方法の一覧を取得できる（支出記録の登録・更新で指定するため）。
- 予算期間を指定して、その予算項目の一覧を取得できる（支出記録の登録・更新で予算を指定するため）。

### REQ-011: 支出記録の登録・更新・削除

利用者が求めたとき、システムは支出記録を登録・更新・削除すること。支払日の指定が省略されたときは、Web アプリの画面と同じく、支出方法と利用日から支払日を自動で算出すること。

**受け入れ条件**

- 支出記録を登録できる。
- 登録済みの支出記録の内容を更新できる。
- 登録・更新で支払日を省略すると、支出方法と利用日から Web アプリが算出した支払日が設定され、自動算出したものとして記録される。
- 登録・更新で支払日を指定すると、その日付が設定され、手入力したものとして記録される。
- 支出記録を削除できる。削除は元に戻せない操作として MCP クライアントに示される。
- 入力の誤りなどで Web アプリが受け付けなかったときは、失敗としてその理由（Web アプリが示す範囲）を示す。

### REQ-012: Web アプリの失敗の伝え方

Web アプリの API の呼び出しが失敗したとき、システムはその種類が分かる一文を、ツールの結果として MCP クライアントに示すこと。

**受け入れ条件**

- 入力不正、対象なし、重複などの業務上の失敗は、それと分かる一文で示される。
- API キーが無効・失効・期限切れのときは、MCP サーバの設定の見直しが必要であることが分かる一文で示される。
- 機能を利用する権限がないときは、その旨が分かる一文で示される。
- Web アプリに接続できないときは、その旨が分かる一文で示される。
- 示す文に、API キー、接続先の URL、内部の例外の内容は含まれない。
- 失敗した登録・更新・削除を自動で再実行しない。

### REQ-013: 操作の記録（ログ）

サインイン、接続の許可・取り消し、ツールの呼び出しが試みられたとき、システムは当該試行の記録を log フォルダへ出力すること。

**受け入れ条件**

- サインインの成功・失敗、接続の許可・取り消し、ツールの呼び出しと、その結果が log フォルダ配下のファイルに残る。
- 記録にはタイムスタンプと区分（INF、WRN、ERR、DBG のいずれか）が含まれる。
- 記録には、ツール名、サイトの識別子、判断に使う値（識別子・日付・件数）、Web アプリの応答の種類が含まれる。
- パスフレーズ、API キー全体、接続の維持に使う秘密の値は記録に含まれない。
- 予定・グッズ・ノウハウ・支出記録の本文やメモなどの内容は記録に含まれない。
- ファイルはサイズが大きくなったら新しいファイルへ切り替わる。

## 認証の要否

MCP サーバのツールは、すべてサインイン済みの MCP クライアントからだけ使える（REQ-001、REQ-002）。サインインの画面そのものは認証不要とし、パスフレーズで利用者を確かめる。

Web アプリへの要求は、サイトごとに MCP サーバが保持する API キーで認証する。Web アプリ側の利用可否（機能の割当）は Web アプリが判定する。

## スコープ外

- 利用者が複数いる場合の、利用者ごとの接続の区別
- 次の操作（Web アプリには存在するが、主要な操作に含めないもの）
  - スケジュール: カテゴリの登録・更新・削除、表示設定、祝日・ユーザ休日、ルーチン
  - グッズ管理: 人物・アーティスト・媒体の登録・更新・削除、人物に関連するアーティスト・媒体の一覧、グッズの画像の追加・削除
  - ノウハウ管理: 大項目・中項目の登録・更新・削除、中項目ごとのノウハウの一覧、表示順の入れ替え
  - 経費管理: 予算期間・予算項目の登録・更新・削除・複製、支出方法の登録・更新・削除、支払予定日の算出だけを単独で行うこと（支出記録の登録・更新の中での算出は対象とする）
- Web アプリの API に存在しない操作
- Web アプリのその他の機能（ノート管理、レシピ管理など）
- MCP クライアント以外（ブラウザなど）からの直接の利用
- サインインの画面以外の画面（サイト・API キーの管理は設定ファイルで行う）
