# ログ出力

> 常時適用（契機・区分・ローテーションの基本方針）

MCP サーバがファイルへ出す記録の方針。ツールの出力とは別である。

## 出力先

- 自サーバの `server/log/` へ出力する。
- ファイルサイズでローテーションする。上限サイズと世代数は、`server/.env` で持つ（`LOG_MAX_BYTES`、`LOG_BACKUP_COUNT`）。
- ログファイルはリポジトリに含めない。

## 1行の内容

タイムスタンプ、区分、メッセージをこの順で出す。

区分は次のいずれかとする。

- **INF**: 正常な処理の進行（ツール呼び出しの受付、成功）
- **WRN**: 想定内だが正常系ではない（認証ヘッダなし、Web アプリが 4xx を返した、入力不正）
- **ERR**: 想定外の失敗（未処理例外、Web アプリへの接続失敗・5xx・タイムアウト）
- **DBG**: 調査用の詳細。本番では出さなくてよい

## 契機

次を契機として出力する。省略しない。

- **入力された内容**: ツール名、サイトの識別子、判断に使う引数（識別子、日付、件数など）、使った API キーの先頭 12 文字
- **それを元にした判断結果**: 呼び出した Web アプリの API（メソッド・パス）、その状態コード、ツールの成功・失敗
- **正常系ではない場合の理由**: ツールの出力には出さない内部理由も含める
- **MCP クライアントの認証**: アクセストークンの検証の成功・失敗（失敗の理由: なし・無効・期限切れ・対象違い）
- **OAuth の処理**: クライアント登録（クライアント名・リダイレクト URI・許可リストとの照合結果）、サインイン（成功・失敗・ロック中）、トークンの発行・更新・失効（クライアント ID）、運用コマンドによる一括失効

```
# ✅ GOOD
2026-09-26 12:00:00 INF ツール呼び出し tool=schedule_list_categories site=home key=wak_Ab3dEf7h
2026-09-26 12:00:00 INF Web アプリ応答 tool=schedule_list_categories site=home GET /categories status=200 件数=5
2026-09-26 12:00:01 WRN Web アプリ応答 tool=goods_delete_person site=home DELETE /persons/3 status=409 理由=参照あり
2026-09-26 12:00:02 WRN MCP クライアント認証失敗 理由=期限切れ
2026-09-26 12:00:03 WRN サインイン失敗 client=Claude 理由=パスフレーズ不一致 連続失敗=2
```

## 秘密情報・個人のデータ

- Web アプリの API キー全体、パスフレーズ、アクセストークン、リフレッシュトークン、認可コード、クライアントシークレット、`Authorization` ヘッダの値は出さない。
- Web アプリの応答本文や、ツールの引数の自由記述（本文・メモ・タイトルなど）は出さない。識別子・件数・状態コードに留める。
