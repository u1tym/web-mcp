# Web アプリの API の呼び出し方

> `src/**/server/**/*.py`、`specs/**/tool-design.md` を編集するとき

## 契約の正

- 呼び出す API のパス・要求・応答・エラーは、Web アプリの各機能の `api-design.md` に従う（`D:\claude_code\claude_webapp\specs\<feature>\api-design.md`）。
- MCP 側で API の契約を推測・拡張しない。`tool-design.md` には、ツールごとに呼び出す API（メソッドとパス）を書き、Web アプリの `api-design.md` と一致させる。
- Web アプリの DB に直接接続しない。Web アプリの Python を import しない。

## サイト（接続先）

MCP サーバは、複数の接続先を登録できる。接続先の単位を「サイト」と呼ぶ。

- サイトは、識別子、表示名、種別、各機能の API 基点 URL、API キーを持つ。
  - 識別子: 英小文字・数字・ハイフン（例: `home`、`office`）。ツールの引数 `site` に使う。
  - 種別: 呼び出す API の系統。現時点では `claude_webapp`（Web アプリ）だけとする。別の種別を足すときは、本ルールを改訂する。
- サイトの構成（API キー以外）は `server/sites.toml` に書く。ひな型は `specs/templates/sites.example.toml`。
- API キーは `server/.env` に、`SITE_<SITE>_API_KEY` の名前で置く。
  - `<SITE>` はサイトの識別子を大文字にし、ハイフンをアンダースコアにする（例: `home` → `SITE_HOME_API_KEY`）。
- 既定のサイトを `sites.toml` の `default_site` で指定する。
- 起動時に、`sites.toml` の各サイトの API キーが `.env` にあること、既定のサイトが存在することを確かめる。欠けていれば起動しない（エラーの内容はログと標準エラーに出す。API キーの値は出さない）。

### API 基点 URL

- `sites.toml` に、サイトごと・機能ごとに書く。機能のキーは Web アプリの機能名（kebab-case。例: `schedule`、`goods-management`）とする。
- 末尾の `/` の有無は、コードで吸収する。
- あるサイトに、ある機能の URL が無いときは、そのサイトではその機能のツールを使えない（ツールのエラーとして返す）。

### ツールでのサイトの指定

- Web アプリの API を呼ぶツールは、任意の引数 `site`（サイトの識別子）を持つ。省略時は既定のサイトを使う。
- 存在しないサイトを指定したときは、ツールのエラーとして返す。
- 登録済みのサイトの識別子と表示名を返すツールを 1 つ用意する（URL と API キーは返さない）。

## 認証

- Web アプリの API は、そのサイトの API キーを `Authorization: Bearer <API キー>` で送って呼ぶ（Web アプリの `rules/14-security.md` の「API キー認証」）。
- MCP クライアントから受け取ったトークンは、Web アプリへ送らない（`rules/14-security.md`）。
- Cookie は送らない。

## 応答の扱い

Web アプリの API の状態コードを、ツールの結果へ次のように対応付ける。文言は `tool-design.md` で決めてよいが、意味は変えない。

| Web アプリの応答 | ツールの結果 |
|------------------|--------------|
| 2xx | 成功。応答の本文を構造化出力として返す |
| 400 | エラー（入力が不正） |
| 401 | エラー（そのサイトの API キーが無効・失効・期限切れ。MCP サーバの設定の見直しが必要） |
| 403 | エラー（その機能を利用する権限がない） |
| 404 | エラー（対象がない） |
| 409 | エラー（重複・参照ありなど。Web アプリの `detail` をそのまま示してよい） |
| 5xx・タイムアウト・接続失敗 | エラー（Web アプリに接続できない、または処理に失敗した） |

- Web アプリの応答本文の `detail` は、内部理由を含まない文言（Web アプリのルール）なので、エラー文に含めてよい。
- 自動で再試行しない（登録・更新・削除が二重に実行されるのを防ぐため）。
- タイムアウトは `WEBAPP_TIMEOUT_SECONDS` で設定する。
