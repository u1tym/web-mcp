# 要件作成（日本語・EARS）

> `specs/**/requirements.md` を編集するとき

見出しと本文は日本語で書くこと。

`specs/templates/requirements-template.md` に従うこと。

要件は EARS の意味を保ち、日本語の文で記述すること（詳細は `CLAUDE.md`）。

各要件には一意の ID（例: REQ-001）を付与すること。

各要件には受け入れ条件を定義すること。

設計内容（ツール名、入力スキーマ、呼び出す API のパス、HTTP ステータス、ライブラリ）を記述してはならない。
「どの機能の、どの操作を、AI から行えるようにするか」と、認証の要否は書いてよい。

対象とする操作は、Web アプリの API に存在するものに限る。Web アプリに無い操作が必要なときは、その旨を「スコープ外」または「未決事項」に書き、Web アプリ側の SPEC 改訂として扱う。

ユーザがこのファイルを承認するまで、`design.md` を作成しないこと。

承認欄は履歴形式とする（日時・状態・変更概要。詳細は `CLAUDE.md`）。
